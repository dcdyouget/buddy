## 目标

搜索来源卡片、点击打开，与 v1 一致。

## 输入

- v1 `WebSearchSection.tsx`、`ToolSection.tsx` 的分派（工具名 `websearch`）、`.websearch-*` / `.think-section*` 样式；engine `tools/websearch` 的结果 JSON

## 实现要点

| ID | 事项 | 说明 |
|----|------|------|
| S05-11-1 | 专用卡片 | `chat/web_search.rs`：外壳沿用思考块（左 2px 强调色边、右侧圆角、搜索中的光泽与三点加载，二者从 `think_block` 抽成共用函数）；标题栏「搜索图标 + 状态文案 + · 关键词 + 箭头」；默认折叠 |
| S05-11-2 | 展开内容 | 「搜索内容 / 搜索引擎」、说明、「搜索结果（N）」；结果项：序号圆标、来源胶囊、标题链接、最多 3 行摘要、正文读取状态；搜索中「正在等待搜索结果…」；无结果提示；最高 336px，卡内滚动（并入列表的内层滚动让路规则） |
| S05-11-3 | 打开链接 | 结果标题链接经 `markdown::gfm::open_link` → 系统浏览器；`Transcript::set_open_handler` 可替换（自检） |
| S05-11-4 | 数据解析 | 用 `serde_json::Value` 手工解析结果 JSON（不为此给 `buddy-ui` 新增 `serde` 直接依赖）；解析失败按空处理，标题栏仍显示参数里的关键词 |
| S05-11-5 | 图标 | 新增 `ExternalLink` |

### 拦截验证

| # | 改坏 | 结果 |
|---|------|------|
| 1 | 不走专用卡片（当普通工具） | FAIL（搜索中被展开，找不到链接） |
| 2 | 点链接不打开 | FAIL（命中位置无 URL） |
| 3 | 默认展开 | FAIL（搜索中折叠高变成 195） |
| 4 | 标题栏不可折叠 | FAIL（再点标题栏无法收起） |
| 5 | 摘要不限三行 | **仍 PASS** —— 示例摘要在该宽度下不足四行，三行截断无自动化证据，须目检 |

### 顺带修复：T12 不稳定

`chat_preview` 的 T12（流式只重测一行）按帧采样，偶尔把相邻两次行同步并成一次而误报「单次重测 2 行」（本会话中出现 2 次、约每 6 次 1 次）。改为 `Transcript` 在每次同步内部记录「单次同步重测的最大行数」（`max_remeasured_per_sync`），不再依赖采样时机；连跑 8 次全通过，人为把计数 +1 则 FAIL。

## 决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 外壳复用思考块 | 抽出 `think_block::{loader, sheen_layer}` 共用 | v1 的 `.websearch-section` 就是 `.think-section` 的变体（同一份光泽与加载点样式），不各写一份 |
| 默认折叠 | 搜索中也折叠 | v1 `useState(false)`；与通用工具卡「执行中默认展开」不同，故 `Transcript` 对 `websearch` 单独取默认值（`default_open`） |
| 链接悬停 | 只变色，不加下划线 | GPUI 的悬停样式不带文字下划线；v1 悬停有下划线，差异极小 |
| 摘要 3 行截断 | `line_clamp(3)` | 同 v1 `-webkit-line-clamp: 3`；无自动化证据（见拦截 5） |
| 无 favicon | 不做 | v1 的卡片没有 favicon（spec 目标中的「favicon」为旧估计）；来源是文字胶囊 |
| 联网搜索的端到端 | 用模拟事件，不联网 | research-log §19.6 记录本机自动化环境下搜索源不可达；卡片只消费结果 JSON，形状由单测对照 engine 的字段 |
