## 目标

贴底时平滑跟随流式增长；用户上滑立即脱离；回到底部附近重新吸附；「滚动到底部」按钮与 v1 一致。

## 输入

- v1 `ChatPage.tsx`：跟随容差 12px、流式开始重置跟随、按钮仅在非流式且离开底部时显示、有未读时 `has-new-message` 样式
- v1 `src/utils/bottomFollow.ts`、`useSmoothWheelScroll.ts`
- Comet 弹簧常量（阻尼 0.7 / 刚度 0.05 / 质量 1.25，前馈跟踪增长）

## 证据

| 项 | 证据 |
|----|------|
| 实现 | `crates/ui/src/chat/transcript.rs`：`FollowMode::Tail`（用户上滑脱离 / 滚到末尾恢复由框架处理，S00-07 实测）、流式开始时 `set_follow_mode(Tail)`、滚动回调只做延后重绘（陷阱 2）、回到底部按钮与未读脉冲、平滑滚到底 |
| T18 | 真实滚轮事件：流式中上滑 → 脱离跟随且视口首行不再变；流式中不显示按钮、结束后显示；点按钮 → 回底且恢复跟随；脱离状态下发送 → 恢复跟随（v1 `useEffect([isStreaming])`）。拦截：去掉「流式开始恢复跟随」→ FAIL |

## 决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 弹簧 | **不做**，按 v1 直接贴底 | v1 跟随为 `scrollTop = scrollHeight` 直接定位（无弹簧）；任务文档的「Comet 弹簧 + 前馈」是超出 v1 的改进，按「以 v1 代码为准」不纳入；若目检觉得流式跟随生硬再议 |
| 脱离 / 恢复判定 | 用 GPUI `FollowMode::Tail` | 与 v1 语义一致（上滑立即脱离、回到底部恢复）；v1 的 12px 容差 vs 框架「到达末尾」差别很小，交目检 |
| `bottomFollow.ts` 移植 | 不移植 | 其作用（区分「几何在底部」与「跟随意图」）由框架的跟随状态承担；research-log §16.2 推论 |
| 按钮滚动 | 约 250ms 递减步长滚到底再恢复跟随；减弱动效时直接到底 | v1 `behavior: 'smooth'`；GPUI 列表无平滑滚动接口 |
