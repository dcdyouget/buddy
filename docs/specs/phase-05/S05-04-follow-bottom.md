- Comet 弹簧常量（阻尼 0.7 / 刚度 0.05 / 质量 1.25，前馈跟踪增长）

## 决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 弹簧 | **不做**，按 v1 直接贴底 | v1 跟随为 `scrollTop = scrollHeight` 直接定位（无弹簧）；任务文档的「Comet 弹簧 + 前馈」是超出 v1 的改进，按「以 v1 代码为准」不纳入；若目检觉得流式跟随生硬再议 |
| 脱离 / 恢复判定 | 用 GPUI `FollowMode::Tail` | 与 v1 语义一致（上滑立即脱离、回到底部恢复）；v1 的 12px 容差 vs 框架「到达末尾」差别很小，交目检 |
| `bottomFollow.ts` 移植 | 不移植 | 其作用（区分「几何在底部」与「跟随意图」）由框架的跟随状态承担；research-log §16.2 推论 |
| 滚轮平滑滚动（目检反馈后补） | 移植 v1 `useSmoothWheelScroll`：捕获阶段接管列表区域纵向滚轮，行 × 20px 换算、累加目标、每帧走剩余 28%、差 0.5px 停；外部改动滚动位置时放弃旧目标 | 目检反馈「向上滚动是逐行的」：GPUI 列表对鼠标滚轮的「行」增量直接按 20px/行跳动；v1 在 WebKit 上用该 hook 做了缓动（`ChatPage.tsx` 引用），迁移时遗漏 |
| GPUI 贴底位置的坑 | 滚动前把「末尾」表示换成等价显式位置 | 贴底时列表位置为「最后一项之后」，`scroll_by` 按内容总高计算 → 上滑不足一屏被夹回底部（T18 在接管滚轮后发现） |
| 按钮滚动 | 约 250ms 递减步长滚到底再恢复跟随；减弱动效时直接到底 | v1 `behavior: 'smooth'`；GPUI 列表无平滑滚动接口 |
