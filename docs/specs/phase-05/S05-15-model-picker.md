# S05-15 模型选择器

> 状态: `blocked`
> Phase: 05
> 依赖: S05-06, S02-01
> 阻塞: 等待用户目检（`handoff.md` §6.5 第 18 项）
> 退役设计文档: —

## 目标

选择模型：只列出启用的模型；选择后保存为默认模型；流式中不可选；紧凑气泡里也能用。

## 输入

- v1 `ModelDropdown.tsx`、`src/utils/modelMenu.ts`、`InputDock.tsx` 的模型按钮、`.model-dropdown*` 样式、configStore `setDefaultModel`

## 实现要点

| ID | 事项 | 说明 |
|----|------|------|
| S05-15-1 | 原生菜单评估 | GPUI 没有原生弹出菜单：`App::set_menus` 只管菜单栏，`WindowKind::AnchoredPopup` 在 macOS 上被拒绝（`gpui_macos/src/platform.rs`）。结论：用一个独立的无边框 `PopUp` 窗口承载 v1 下拉的外观，按模型按钮的屏幕位置摆放 —— 与 v1 原生菜单同样「独立于主窗口绘制，紧凑气泡无需扩高」 |
| S05-15-2 | 菜单 | `chat/model_menu.rs`：`menu_rows`（Provider 启用的模型）、`detail_text`（`Provider · 128K 上下文 · 230ms`）、`ModelMenu`（行、对勾、悬停、Esc、点击外部即失去激活则关闭、选中后 120 ms 关闭并把焦点还给主窗口） |
| S05-15-3 | 定位 | 输入区用绝对定位 canvas 记录模型按钮边界（`Composer::model_button_bounds`）；面板底边在按钮上方 8px、右缘距主窗口右缘 8px；上方放不下时放到按钮下方 |
| S05-15-4 | 保存 | `PageRouter::select_model`：内存立即生效（输入区的图片支持等同步更新），写盘经**串行队列**（v1 `configUpdateQueue`：连选两次时第二次保存不能被第一次覆盖）；失败在错误条提示 |
| S05-15-5 | 流式中禁用 | 流式中输入区不渲染模型按钮（v1 `onModelPickerClick` 为空），边界记录同时清空 |

## 验收标准

- [x] 选择后配置保存（T28：盘上 `selected_model_id` 变化；快速连选三次以最后一次为准）
- [x] 只列出启用的模型、副标题格式、空列表提示（单测 + T28）
- [x] 流式中不可选（T28）
- [ ] 交互 —— **需用户目检**（handoff §6.5 第 18 项）

## 决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 用独立窗口而非页内浮层 | `PopUp` 窗口 | 紧凑窗口只有 60px 高，页内浮层会被窗口裁掉；v1 为此用原生菜单。GPUI 无等价物，独立窗口是最接近的做法 |
| 外观取「下拉」而非原生菜单样式 | v1 `ModelDropdown` 的外观 | v1 的原生菜单是系统绘制的，无法在 GPUI 复现；下拉是 v1 的回退外观，信息更全（副标题、对勾） |
| 阴影 | 窗口四周留 12px 透明边距 | 独立窗口的阴影会被窗口边界裁掉 |
| 点击外部关闭 | 用「窗口失去激活」判定 | 与 v1 的 document mousedown 外部判定等价；首次激活之前的变化忽略，避免刚打开就被关掉。**该路径未做自动化**（自检里无法让窗口真正失去系统激活），须目检 |
| 边框 | `--border-default` 代替 `--glass-outline` | 同 Composer（S05-16 决策记录） |
| 打开中再点按钮 | 关闭 | v1 下拉为切换；点击按钮本身会先让菜单窗口失去激活而自行关闭，随后的点击可能又打开，与原生菜单行为一致，可接受 |
| 保存失败 | 内存已生效、错误条提示 | v1 store 同样先 `set` 再写盘 |
| 模型按钮悬停动画 | 不做 | v1 有 Bot 图标切换 / 问候的 CSS 动画（`model-bot-switch` / `model-bot-greet`），属装饰，非本 spec 范围 |
