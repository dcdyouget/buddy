## 目标

行高按 (行 id, 内容版本, 宽度) 记忆；流式只重测最后一行；视口上方高度变化不造成跳动。

## 输入

- GPUI `ListState` 的高度缓存与 `splice` 语义

## 实现要点

| ID | 事项 | 说明 |
|----|------|------|
| S05-03-1 | 只重测受影响行 | 流式 token 到达只使一行失效 |

## 验收标准

- [x] 流式追加时只有一行被重新测量（计数断言）—— `chat_preview` T12
- [x] 视口上方行高变化后滚动锚点不跳 —— T14（以屏幕坐标断言，见决策记录）

## 证据

| 项 | 证据 |
|----|------|
| 行高记忆 | 由 GPUI `ListState` 的高度缓存（sum_tree）承担：本项目只在行 `version`（内容指纹）变化时 `remeasure_items` 那一行（`chat/transcript.rs` `sync`）；宽度变化时 GPUI 自行使全部缓存失效（`list.rs` prepaint：「If the width of the list has changed, invalidate all cached item heights」） |
| T12 | 流式期间单次最多重测 1 行（见 S05-01 / S05-17） |
| T14 | `chat_preview -- --selftest`：滚到第 500 行，把视口上方第 490 行改长 → 视口首行 `500 + 10px` 不变；视口内一行屏幕 y **120px → 120px**；反证：内容总高 37393 → 37627px（+234px，确有高度变化），且改动行 `item_is_above_viewport = true`；只重测 1 行 |

## 决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 滚动锚点 | 沿用 GPUI 以「行下标 + 行内偏移」记录滚动位置 | 视口上方的行变高不改变该逻辑位置，可见内容天然不动（T14 证实）；无需像 v1 那样手动补偿 scrollTop |
| 目检 | 不单列 | T14 断言的就是屏幕坐标（`bounds_for_item`），与肉眼所见一致；该场景（视口上方行变高）在预览中也难以手动触发。整体滚动观感随目检 #8 |
| 宽度变化 | 接受 GPUI 全部重测 | 用户拖动改窗宽时触发；已加载行数由 S05-05 分页控制，成本随之受限（S05-01 首帧成本数据） |
