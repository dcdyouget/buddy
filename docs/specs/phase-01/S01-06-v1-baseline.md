## 目标

在动任何 UI 代码之前，把当前 v1（Tauri + React）版本的**真实渲染结果**采集为可复核的基线截图与录屏。

**产出物**：`docs/evidence/v1-baseline/` 下的完整基线材料 + 一份索引。

## 为什么必须有这个 spec

原计划用 `docs/design/prototypes/` 作为视觉验收基准，但**审计发现该目录不存在**——它是从 `AGENTS.md` → `CLAUDE.md` → `docs/tasks/v1.0.0/` 一路传播的失效引用。仓库中也不存在任何「7 个页面原型」的 HTML。

因此本重构**唯一可信的视觉基准是当前 v1 应用的实机渲染**。而 v1 的 UI 代码将在 Phase 05 起被逐步替换，**采集必须在此之前完成**，否则基准永久丢失。

## 输入

- `docs/design/pages-and-states.md` —— 页面与状态清单（采集清单依据）
- `docs/design/design-tokens.md` —— 令牌真值（用于核对截图中的实际取值）
- `AGENTS.md` 硬约束 1-10 —— 基线需能支撑这些约束的验收
- 当前可运行的 v1 应用（`npm run tauri dev`）

## 决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 视觉/行为基线形式 | **不截图、不录屏**；由用户对照运行中的 v1 目检并反馈结果（2026-09-26 用户决策） | 用户明确表示「不用录屏，实现之后我来检验」。因此不可再生资产从「截图」转为「**可构建运行的 v1**」—— 它由 `S01-05` 的退路 tag 保证。S01-05 的回退演练必须证明 v1 能从 tag 构建并运行，否则视觉对照基准丢失 |
| 真实数据快照 | **不采集** | 用户：「不用保存历史信息，当前还在开发阶段，不用考虑历史数据迁移」。同时避开了明文 API Key（硬约束 9）入库的泄露风险 |
| 性能采集工具 | `scripts/v1-baseline/perf_baseline.sh` + `winwait.swift`（窗口列表判定上屏、`footprint` 取内存） | 不依赖截图权限；v1 / v2 同一脚本即同口径；沙盒 `HOME` 隔离用户数据 |
| 令牌来源 | 静态解析 `global.css`（而非运行中 WebView 的 computed style） | 令牌全部定义在 `:root` / `html.dark`，展开 `var()` 即为 computed 值；避免为读取 devtools 自动化 WebView |
| 长会话样本形式 | 入库生成脚本，不入库数据 | 固定种子可复现；881 KB 生成物无需进版本库 |
| 基线二进制 | `npx tauri build --no-bundle` | 嵌入前端的 release 二进制；不打 dmg |
