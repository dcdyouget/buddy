# 接手 Prompt（可复制给其他 AI）

> 用途：把 Buddy v2.0.0-gpui 迁移工作交接给新的 agent。
> 使用方式：把下方代码块**整段**复制给新的 AI。
> 维护：项目状态变化时同步更新本文（尤其是「当前该做什么」一节）。

---

【A】状态只在 `docs/specs/README.md` 维护，不另立状态源。

【B】完成一个 spec 立即更新注册表（不批量补记）。

【C】证据必须可复核 —— 不接受「OK」「已完成」这类无信息量结论。
     要 `cargo tree` 输出片段 / 截图 / 录屏 / 具体数值 / commit hash。
     「看似生效实则 no-op」的 API 必须写探测方法与探测结果。

【D】★ **需要眼睛验收的，不得仅凭自己的仪表盘标 done，必须停下来问用户。**

【G】设计文档是脚手架，不是永久资产。代码实现完某份设计文档后**必须删除它**
     并登记 `docs/specs/design-deletions.md`。代码即文档。

【H】任何 GPUI 显示异常，先 `RUST_LOG=debug` 看 gpui 自身日志。

【I】图层/属性探测必须**延迟复探**。首探在首次合成之前，会得到错误结论

## 使用说明（给用户，不要复制这段）

**复制范围**：上面 ````text ... ```` 代码块内的全部内容（不含本节）。

**如果新 agent 的环境不同**（比如代理端口不是 7890），在 prompt 里改掉第三节的
`export` 那几行，或让它自己读 `docs/dev-environment.md` §2。

**想让它只做一个具体的 spec** 时，在最后追加一句，例如：

```text
本次只做 S02-01（providers 移植）。做完停下来汇报，不要继续下一个。
```

**新 agent 常犯的三个错**（可在 prompt 末尾重申）：

1. 只读 `AGENTS.md` 就开始写代码 —— 会漏掉 `handoff.md` 里的坑
2. 看到文档写「毛玻璃」「prototypes/」就当真 —— 那两处是「从未存在的意图」
3. 自己跑通仪表盘就宣布完成 —— 必须让用户看
