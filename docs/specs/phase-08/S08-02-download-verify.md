# S08-02 下载 / sha256 校验 / 验签

> 状态: `done`
> Phase: 08
> 依赖: S08-01
> 阻塞: —
> 退役设计文档: —

## 目标

流式下载更新包并在落盘后同时满足大小、sha256、minisign 签名三项校验，任一失败即丢弃。

## 输入

- `docs/tasks/v2.0.0-gpui/08-release.md` D05–D07
- Tauri signer 的签名 / 公钥外层编码（base64 包裹的 minisign 文本）

## 实现要点

| ID | 事项 | 说明 |
|----|------|------|
| D05 | 下载 | `reqwest` 分块读取，边写边算 sha256，超过声明大小立即中止；进度回调给设置页 |
| D06 | 完整性 | 大小与 sha256 必须与清单完全一致 |
| D07 | 签名 | `minisign-verify` 只接受预哈希签名（`ED`）；验证的是落盘内容 |
| — | 缓存 | `~/Library/Caches/com.buddy.chat/updates/<版本>/`，每次下载前清空，下次启动清理 |
| — | 密钥 | v1 私钥密码遗失，v2 首发前换用 `~/.tauri/buddy-v2.key`；公钥内置于 `PUBLIC_KEY` |

## 验收标准

- [x] Tauri signer 产出的真实签名可验证；篡改内容、其他密钥签名、乱码签名被拒绝
- [x] 内置公钥与发布私钥配对（以发布私钥的真实签名固定为测试）
- [x] 大小 / sha256 不一致被拒绝；URL 文件名不能逃逸缓存目录
- [x] 线上真实更新包完成下载与三项校验

## 证据

| 项 | 证据 |
|----|------|
| 单测 | `verify.rs` 6 项（一次性测试密钥签名通过、篡改拒绝、产品公钥拒绝测试密钥签名、产品公钥可解析、乱码拒绝、`product_key_verifies_release_signature` 用 `buddy-v2.key` 的真实签名通过）；`download.rs` 2 项（大小 / 哈希不一致、`a%2F..%2Fb` 回退为固定文件名） |
| 线上 | 见 S08-03 证据：0.1.0 更新包下载 100% 后打印「sha256 + 签名校验通过」 |

## 决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 签名格式 | 沿用 Tauri signer（minisign + 外层 base64） | 发布机已有工具链（`node_modules/.bin/tauri signer sign`），无需另装 minisign |
| 更换密钥 | 新建 `buddy-v2.key` | 旧私钥密码遗失；v2 尚未发布任何客户端，此时更换没有代价。用户 2026-10-04 选择 |
| 拒绝旧式签名 | `allow_legacy = false` | 现有工具只产出预哈希签名，拒绝旧式可缩小攻击面 |
