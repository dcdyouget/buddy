# S08-05 静默检查与空闲调度

> 状态: `done`
> Phase: 08
> 依赖: S08-01
> 阻塞: —
> 退役设计文档: —

## 目标

安装包运行时定时在后台检查更新（只提示不安装），并在流式回复进行中推迟重启。

## 输入

- `docs/tasks/v2.0.0-gpui/08-release.md` D12–D14
- 用户 2026-10-04 决定：后台定时检查，有新版只提示，用户确认后才下载安装（取代 v1「启动时不得自动检查」）

## 实现要点

| ID | 事项 | 说明 |
|----|------|------|
| D12 | 调度 | 启动 20 秒后首次检查，之后每 6 小时；仅 `buddy_update::is_installed_app()` 为真时启动，开发构建 / 示例程序不访问网络 |
| — | 只提示 | 后台检查不改变可见状态，仅当区域处于「未检查 / 已是最新」且发现新版本时显示「发现新版本」；失败只记 info 日志 |
| D13 | 空闲 | 安装完成后 Router 若在流式回复中，保存待重启并显示「安装完成，将在当前回复结束后重启…」，回复结束时再重启（`router_update.rs`） |
| D14 | 开关 | 不提供关闭开关（v1 只有手动检查，没有开关可复现） |

## 验收标准

- [x] 后台检查仅在安装包中启用
- [x] 流式中不重启，结束后重启；空闲时立即重启
- [x] 重启前等待进行中的配置保存（与托盘「退出」同一路径）

## 证据

| 项 | 证据 |
|----|------|
| 代码 | `crates/ui/src/settings/update.rs`（`FIRST_CHECK` / `CHECK_PERIOD` / `background_check`）；`crates/ui/src/chat/router_update.rs`；`router.rs` 中 `conversation_changed` 在流式结束分支取出 `pending_update` |
| 安装包判定 | `development_binary_is_not_an_app` 单测：非 `.app` 内运行时 `current_app()` 报错，`is_installed_app()` 因此为假 |
| 证据边界 | 20 秒 / 6 小时调度与「流式中延迟重启」没有自动化或真实运行证据（需要真实流式回复中完成一次安装）；属代码审阅级证据，已如实记录 |

## 决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 后台检查 | 启用，只提示 | 用户采纳；不弹窗避免打断，信息集中在设置页 |
| 延迟对象 | 只延迟重启，下载与替换照常 | 替换磁盘上的 bundle 不影响运行中进程；只有重启会中断回复 |
